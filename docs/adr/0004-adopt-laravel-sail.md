# 0004 — Adopt Laravel Sail for Docker Dev

**Date:** 2026-07-23

## Status

Accepted (supersedes #1 / PR #10).

## Context

Issue #11 asks for a one-command Docker dev environment where every common
operation (serve, queue, logs, Vite, migrations, tests, tinker, npm) runs inside
the container, while the non-Docker host workflow stays unchanged. PR #10
delivered this with a hand-rolled `Dockerfile.dev` + `docker-compose.yml` +
`docker-entrypoint.dev.sh`. That worked, but it maintains a parallel Docker
infrastructure that duplicates what Laravel Sail already provides and keeps
tested upstream (PHP 8.5 runtime, extension set, gosu user-mapping, the `sail`
CLI).

Two hard constraints shaped the decision:

1. **sqlite-only.** This project's default (and only) database is sqlite. The
   DB file and `storage/logs` must persist on the host across `sail stop` /
   `sail up`. Sail's default installer pulls in mysql/redis/mailpit/etc., which
   we explicitly do not want.
2. **Preserve `composer dev`.** The one-command dev orchestration
   (`artisan serve` + `queue:listen` + `pail` + Vite, wired through
   `npx concurrently`) must run inside the container so the same command serves
   host and Docker workflows.

## Decision

**Adopt Laravel Sail** (`laravel/sail` dev dependency, PHP 8.5 runtime), with a
sqlite-only `compose.yaml` generated by `php artisan sail:install --with=none`
and then customised for this project. Remove every hand-rolled Docker artifact
from #1 / PR #10 — no `Dockerfile.dev`, no `docker-compose.yml`, no
`.dockerignore`, no `docker-entrypoint.dev.sh`. The only committed Docker file
is the Sail-managed `compose.yaml`; the image is built from
`vendor/laravel/sail/runtimes/8.5`.

Customisations layered on top of Sail:

- **App command = `composer dev`.** The `laravel.test` service overrides Sail's
  default php-fpm with `composer dev`, so `sail up` brings up the full stack
  (serve + queue + pail + Vite) via the existing orchestration. Sail's
  `start-container` entrypoint still runs, dropping privileges to the `sail`
  user via `gosu` before exec'ing the command.
- **No database service.** `--with=none` yields a compose file with only the app
  container. sqlite (`database/database.sqlite`) and `storage/logs` persist
  because the project dir is bind-mounted.
- **Isolated `node_modules`.** Vite 8 / rolldown, lightningcss and Tailwind ship
  platform-specific native binaries. Sharing one `node_modules` tree between a
  macOS host and a Linux container breaks whichever platform didn't install it.
  A named volume (`sail-node-modules`) gives the container its own Linux-native
  tree; the host keeps its platform-correct one. A one-shot `node-setup` service
  (runs as root only to `chown` the empty volume, then `npm ci` as `sail`)
  bootstraps it before the app starts and is a no-op on warm starts. `npm ci`
  (not `npm install`) is used so the bind-mounted `package-lock.json` is never
  rewritten. This is the same isolation PR #10 arrived at — Sail does not do it
  by default.
- **`0.0.0.0` binding.** `php artisan serve --host=0.0.0.0` (in the `composer
  dev` script) and `server.host: '0.0.0.0'` in `vite.config.js` make the servers
  reachable from the host browser through the published ports. This is benign on
  the host (`localhost:8000` still resolves to loopback) and required for the
  container.

Rejected alternative: **keep PR #10's hand-rolled stack.** Rejected because it
duplicates Sail's maintained runtime and CLI for no gain; Sail gives the same
result (PHP 8.5, all extensions incl. `pcntl`/`pdo_sqlite`, non-root user) with
the image build owned upstream.

## Consequences

- One command (`sail up`) brings up the whole dev stack; `sail test`,
  `sail artisan migrate`, `sail tinker`, `sail npm …` all run in-container.
- `compose.yaml` carries two intentional deviations from Sail's defaults
  (`composer dev` command + node-setup service). These are documented inline and
  guarded by `tests/Unit/SailDevEnvironmentTest.php`.
- `phpunit.xml` stays sqlite `:memory:`; Sail's installer rewrites it for a
  `testing` DB by default, so we do not run the full installer blindly — the
  guard test fails if the sqlite testing config is lost.
- Host workflow (`composer dev`, `php artisan …`, host `php artisan test`) is
  unchanged; only the benign `0.0.0.0` bind flags were added.
- Image bloat: Sail's runtime is a large general-purpose image (many extensions,
  Node, playwright deps). Acceptable for a dev-only environment; not used in
  production (out of scope).
